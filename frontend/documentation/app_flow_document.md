# Cafe Ordering App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new user arrives at the cafe ordering website, they land on a public homepage that introduces the brand and highlights key features. From here, they can choose to browse the menu without signing in, or they can click the Sign Up or Sign In links in the header navigation. To register, the user selects the Email sign-up option, enters their name, email address, and a password, then submits the form. Upon successful registration, they are automatically logged in and redirected to their dashboard. If the password is forgotten, the user clicks the “Forgot Password” link on the Sign In page, enters their email address, and receives an email with a password reset link. Following the link takes them to a reset form where they provide a new password. Once they reset it successfully, they can sign in with their new credentials. Signing out is accomplished by clicking the Logout button in the site header or sidebar, which clears the session and takes the user back to the public homepage.

## Main Dashboard or Home Page
After signing in, the user lands on a personalized dashboard. Customer users see a welcome banner, quick links to the Menu, Cart, Order History, and Profile sections in a sidebar. The header displays their name and a cart icon showing the current number of items. Admin users see a different dashboard layout with summary cards showing total orders today, pending requests, active menu items, and user count. Their sidebar presents links to Menu Management, Order Management, User Management, and Settings. Both dashboards share a consistent visual style, and clicking any sidebar link changes the main content area to that corresponding section while keeping the sidebar and header visible at all times.

## Detailed Feature Flows and Page Transitions
### Customer Menu Browsing and Ordering Flow
A signed-in customer clicks the Menu link in the sidebar to view all available products. The system fetches the product list from the server and displays each item as a card with name, image, description, and price. When the customer clicks “Add to Cart,” the item is stored in the client-side cart state and the cart icon in the header updates immediately. To review or modify their selection, the user clicks the Cart link in the sidebar. On the Cart page, they see each line item, can adjust quantities or remove items, and view the updated total price. Clicking the Proceed to Checkout button takes them to a Checkout page where they confirm the order summary and click Place Order. The app sends the order details to the server via a POST request; upon success, the user is redirected to an Order Confirmation page showing their order number and estimated preparation time. A button on this page then guides them to their Order History section.

### Customer Order History and Details
In Order History, the user sees a list of their past orders sorted by date. Each entry shows the order number, date, total amount, and current status. Clicking on an individual order opens a detail view that breaks down the items ordered, quantities, per-item cost, and total. From this view, the customer may choose to reorder the same selection, which repopulates their cart and navigates them back to the Cart page.

### Admin Menu Management Flow
An admin clicks Menu Management in the sidebar to manage cafe products. The page loads a data table of existing menu items with columns for name, price, category, and status. A Create New Product button opens a modal containing a form for entering product details and uploading an image. Submitting the form sends a POST request; on success, the new product appears in the table. To edit an item, the admin clicks an Edit icon on the row, modifies fields in an inline form or modal, and saves changes via a PUT request. A Delete icon prompts a confirmation dialogue; confirming sends a DELETE request and removes the item from the list.

### Admin Order Management Flow
Selecting Order Management displays a list of all incoming and past orders in a paginated table. Each row shows the order ID, customer name, date, total price, and current status (Pending, In Progress, Completed). Clicking a row opens a detail panel where the admin can view line items and customer notes. A status dropdown in this panel allows updating the order status; changing it sends a PATCH request and immediately updates the table. There is also a Refresh button to fetch the latest order data from the server.

### Admin User Management Flow
Within User Management, the admin sees a list of all registered users with their emails, names, roles (admin or customer), and account status. An Edit link opens a form for changing a user’s role or deactivating an account. Saving these changes sends a server request and updates the list. Deleting a user triggers a confirmation prompt before sending a DELETE request.

## Settings and Account Management
Both customer and admin users can access a Settings page via the sidebar. Here they see sections for Personal Information, Security, and Notification Preferences. In Personal Information, they update their name and contact email; saving triggers a PATCH request to update the user record. In Security, they can change their password by providing their current and new password, then submitting a secure request to the password update endpoint. Notification Preferences allow toggling email alerts for order updates or administrative announcements. After saving changes, a subtle success message appears and the user may navigate back to any dashboard section via the sidebar or header links.

## Error States and Alternate Paths
If a user enters invalid login credentials, the Sign In form displays an inline error message prompting them to try again. During registration or password reset, if the email is already in use or the reset code is invalid, clear error text explains the problem. When fetching data, if the network is down or the server returns an error, a friendly banner appears at the top of the content area advising the user to check their connection and retry. Attempting to access an admin-only page as a customer redirects to an Access Denied page with a link back to the customer dashboard. Nonexistent URLs bring up a custom 404 page with navigation back to the home or login screen. All forms include client- and server-side validation, and any operation failure shows context-specific feedback so the user always knows how to correct or retry.

## Conclusion and Overall App Journey
From first landing on the site and signing up to placing orders or managing cafe operations, the user journey is cohesive and intuitive. Customers enjoy a simple path from menu browsing to order confirmation and can seamlessly review past orders or reorder favorite items. Admin users have a clear, role-protected interface for controlling menu content, monitoring and updating order statuses, and overseeing user accounts. Throughout the app, consistent navigation, immediate feedback, and robust error handling ensure every action moves the user smoothly toward their end goal—whether that is enjoying a cafe meal or running a successful online ordering system.
